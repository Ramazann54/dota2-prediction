# Dota 2: когда исход матча становится предсказуемым

> **С какой минуты исход рейтингового матча Dota 2 становится предсказуемым, и сколько в этом даёт драфт, а сколько — ход игры?**

🚧 Проект в работе

## О проекте

Исследование свежих рейтинговых матчей Dota 2 (только текущий патч) с помощью статистики и вероятностных моделей.

Строятся две модели вероятности победы:
- **до игры** — только по драфту (10 выбранных героев);
- **по ходу игры** — по состоянию матча на минуте t: разница в золоте и опыте, башни, время.

Модели оцениваются не только по точности, но и по **калибровке**: если модель даёт 70%, такие матчи должны выигрываться примерно в 70% случаев.

## Что планируется получить

- Кривую предсказуемости: как растёт качество прогноза от 0-й к 30-й минуте
- Вклад драфта по сравнению с простым ориентиром (baseline)
- Таблицу камбэков: шанс отыграться при отставании в золоте на разных минутах
- Оценку того, сколько стоит преимущество в золоте на 10-й и на 30-й минуте
- Скорость устаревания модели при изменении меты
- Поминутный график шанса на победу для любого разобранного матча

## Данные

Источник — [OpenDota API](https://docs.opendota.com/) (бесплатный тариф, около 2000 запросов в день).

| Эндпоинт | Что даёт | Для чего |
|---|---|---|
| `/publicMatches` | герои, победитель, ранг, режим (100 матчей за запрос) | модель по драфту |
| `/parsedMatches` + `/matches/{id}` | поминутное золото и опыт, события матча | модель по ходу игры |

### Проблемы в данных, найденные на этапе разведки

- **Пустые матчи.** Часть записей содержит героев `0` и длительность `0`, при этом `radiant_win = false` стоит по умолчанию. Без фильтрации это искусственно завышает винрейт Dire.
- **Другие режимы.** В выборке около 55% матчей в режиме Turbo, есть игры с ботами и режим новичков. Обычных рейтинговых матчей (`lobby_type = 7`, `game_mode = 22`) около 12%.
- **Смещение по длительности.** Среди самых свежих матчей в выдаче оказываются только быстро закончившиеся игры, потому что длинные ещё идут. Поэтому сбор идёт с отставанием по времени (листаем назад через `less_than_match_id`).
- **Шумный ранг.** `avg_rank_tier` иногда посчитан по одному игроку (`num_rank_tier = 1`).
- **Утечка данных.** Итоговые статы игроков (убийства, GPM) известны только после матча и не используются как признаки.

## Методология

- Делим данные **по времени**, а не случайно: обучаем на ранних матчах, проверяем на более поздних
- Сравниваем с простыми ориентирами: «всегда Radiant», сумма винрейтов героев
- Основная модель — логистическая регрессия (интерпретируемые коэффициенты), градиентный бустинг используется для сравнения
- Метрики: log loss, Brier score, калибровочный график
- Доверительные интервалы через bootstrap, поправка на множественные сравнения при анализе героев
